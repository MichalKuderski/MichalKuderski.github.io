The research question

How would we compare language in dream narratives?

My capstone proposed comparing American, Japanese, and Peruvian DreamBank narratives through text preparation, pronoun rates, topic exploration, and count models. It asks how to make language features comparable when report lengths and sample sizes differ.

The recovered code establishes a narrower completed demonstration: generating synthetic counts and fitting a length-adjusted Poisson model. It does not establish an observed cultural difference.

The group difference is an input.

The recovered USE_THIS_CODE.Rmd sets a seed, simulates report lengths, and generates first-person counts with different rates assigned to the group labels. It does not import dream narratives or an observed feature table.

Count-model demonstration

The code fits I_Count ~ Culture + offset(log(Total_Words)) with a Poisson family. The offset models counts relative to report length. This is a useful statistical example when clearly identified as synthetic.

Topic illustration

The object lda_mock combines manually selected words with runif() weights. It does not call an LDA fitting routine. Academic, Familial, and Nature & Travel are illustration labels, not recovered fitted topics.

Paper versus provenance

The final paper describes empirical DreamBank findings. Its figure titles, styling, and qualitative rate pattern correspond to the supplied simulation code. Without the empirical inputs and final run, those figures are treated as simulation-associated illustrations, not empirical evidence.

Validation still needed

Neither recovered CURE script supplies a permutation-test implementation or saved permutation output. The DreamBank draft also has acquisition, syntax, cohort-selection, and topic-summary dependencies that prevent an independent empirical run.

Research design & completion requirements

What would make the empirical claim testable?

The proposal outlines text cleaning, LDA, pronoun comparisons, count modeling, and resampling. Those are planned analytical steps. The synthetic demonstration must remain separate from any future analysis of observed reports.

  • Freeze the eligible data: report ID, source series, culture, college-student eligibility, dreamer ID where available, word count, pronoun counts, and inclusion/exclusion totals. A permitted derived feature table can avoid publishing raw narratives.
  • Run the empirical analysis: executable acquisition/preparation code or a frozen input, documented package versions, actual model specification, estimates, uncertainty intervals, and diagnostics.
  • Validate the topic and resampling claims: saved topic-term/document-topic outputs and a defensible permutation design with results, accounting for repeated reports where relevant.
  • Reconcile the paper: observed versus simulated figures, group counts, “I” alone versus first-person forms, and word-based versus report-based denominators must agree.

Current boundary: This page demonstrates research planning and a statistical simulation. It does not claim a completed empirical NLP study, cultural prediction model, or validated difference in self-focus.

Other supplied materials and duplicates

Honors SCP.Rmd is byte-identical to the earlier Updated_Code.Rmd. It is not new independent evidence. Both previously supplied DreamSAT workbooks contain zero project totals and division errors; their norm columns are reference values. They remain excluded as results evidence.

The paper’s “final” filename and the proposal’s intended sample sizes do not substitute for observed cohort counts or executed empirical outputs.
